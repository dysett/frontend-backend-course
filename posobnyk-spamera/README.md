# Пособник спамера

Готовий навчальний клієнт-серверний застосунок «Листоноша» для вправи із силабусу Front- та BackEnd-технологій веб-застосувань. Сервер працює на **Node.js та Express**, контакти й журнал розсилок зберігаються в **MongoDB**, інтерфейс використовує **Twitter Bootstrap 5**, листи формує **Nodemailer**. На вимогу викладача сторінку формує серверний шаблонізатор **Pug**.

## Швидкий запуск

Потрібні Node.js 22 або новіший і npm. Відкрийте термінал у папці `posobnyk-spamera`:

```powershell
npm ci
npm run demo
```

Перейдіть на **http://127.0.0.1:3000**. Зупинка сервера: **Ctrl+C**.

`demo` запускає справжній окремий процес MongoDB через допоміжний пакет `mongodb-memory-server`. Під час першого запуску пакет може завантажити виконуваний файл MongoDB з офіційного сервера MongoDB, тому потрібен Інтернет. У цьому проєкті використано сховище **WiredTiger на диску**: контакти та історія зберігаються в `.data/mongodb` і залишаються після перезапуску. Це окрема демонстраційна база `posobnyk_spamera_demo`. Порт MongoDB обирається автоматично. Перший запуск додає 8 вигаданих контактів, якщо список порожній.

У режимі `demo` листи **не надсилаються в Інтернет**. Кнопка «Підготувати листи» створює повні MIME-листи у файлах `.eml` у папці `outbox`. Їх можна завантажити з деталей розсилки й відкрити у поштовій програмі. Демонстраційні адреси `example.com` потрібно замінити власними для перевірки реальної доставки.

## Запуск у WebStorm

1. Виберіть **File → Open** і відкрийте саме папку `posobnyk-spamera`.
2. У налаштуваннях Node.js виберіть встановлений інтерпретатор Node.js 22+.
3. Відкрийте **Terminal** і виконайте `npm ci`.
4. Виконайте `npm run demo`. Також можна запустити npm-скрипт `demo` з `package.json` через кнопку запуску біля скрипта.
5. Відкрийте http://127.0.0.1:3000 у браузері.

Для налагодження звичайного режиму створіть конфігурацію **Node.js** із JavaScript-файлом `src/server.js` та робочою папкою проєкту. Аргумент `--demo` вмикає демонстраційну базу та перегляд листів. Файл `requests.http` містить запити для HTTP Client WebStorm.

## Запуск із власною MongoDB

1. Запустіть локальний сервер MongoDB або підготуйте URI власної бази.
2. Створіть файл налаштувань:

```powershell
Copy-Item .env.example .env
```

3. У `.env` задайте URI й назву бази:

```dotenv
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB=posobnyk_spamera
MAIL_MODE=preview
```

4. За бажанням додайте вигадані демонстраційні контакти та запустіть застосунок:

```powershell
npm run seed
npm start
```

`npm run seed` не очищає базу й не переписує наявні контакти з такими самими адресами. Для MongoDB Atlas можна вказати власний `mongodb+srv://…` URI. Пароль із URI тримайте тільки в `.env`.

## Реальне надсилання через SMTP

Налаштуйте `.env` для свого поштового сервера. Наприклад, якщо сервер підтримує STARTTLS на порту 587:

```dotenv
MAIL_MODE=smtp
MAIL_FROM="Ваше ім’я <your-account@example.org>"
SMTP_HOST=smtp.example.org
SMTP_PORT=587
SMTP_SECURE=false
SMTP_REQUIRE_TLS=true
SMTP_USER=your-account@example.org
SMTP_PASS=your-smtp-password
```

Для порту 465 із TLS від початку з’єднання задайте `SMTP_PORT=465` і `SMTP_SECURE=true`. Використовуйте реквізити, які надав ваш поштовий сервіс; для деяких сервісів потрібен окремий пароль застосунку. `MAIL_FROM` має відповідати дозволеному відправнику вашого SMTP-сервера.

Запустіть **`npm start`**, а не `npm run demo`: демонстраційний режим завжди створює локальні файли. Після зміни `.env` перезапустіть сервер. У верхній частині інтерфейсу з’явиться «Надсилання через SMTP», а кнопка матиме назву «Надіслати листи».

Кожен адресат отримує **окремий лист**. Інші адреси не додаються до `To`, `Cc` або `Bcc`. Помилка для однієї адреси не перериває обробку решти. Статус «Прийнято SMTP» означає, що SMTP-сервер прийняв листа; фактичне потрапляння до скриньки залежить від поштових серверів.

Для локального SMTP-перехоплювача без TLS можна явно задати `SMTP_REQUIRE_TLS=false`. За замовчуванням STARTTLS обов’язковий.

## Робота з інтерфейсом

- **Контакти**: перегляд за українським алфавітом, сортування за прізвищем або email в обох напрямках, пошук, пагінація по 8 записів.
- **Додати контакт**: заповніть прізвище, ім’я, по батькові та email. Усі поля обов’язкові.
- **Редагування та вилучення**: кнопки олівця й кошика біля кожного контакту. Вилучення потребує підтвердження у вікні застосунку.
- **Нова розсилка**: виберіть увесь список або конкретних адресатів. Їх можна попередньо позначити в таблиці контактів.
- **Шаблони листів**: три готові повідомлення. Шаблон заповнює тему й текст. Після зміни теми або тексту повідомлення стає власним.
- **Попередній перегляд**: показує тему та текст до запуску розсилки.
- **Історія розсилок**: останні 30 розсилок із часом, режимом, кількістю успішних і невдалих спроб. «Деталі» показують результат для кожного адресата та завантаження `.eml` у режимі перегляду.

Порожній список або порожній текст не можна надіслати. Одна адреса може бути у базі лише один раз. Ліміт однієї розсилки задається через `MAX_RECIPIENTS`, за замовчуванням 200.

## Перевірка

```powershell
npm run check
npm test
```

`check` перевіряє синтаксис JavaScript і компіляцію шаблонів Pug. Інтеграційні тести використовують окрему тимчасову MongoDB та локальний SMTP-сервер. Перевіряються серверне відображення Pug, CRUD, сортування, валідація, унікальність email, вибрані адресати, шаблони й власний текст, створення `.eml`, часткові помилки, одночасні запити, збереження історії та реальна SMTP-передача. Інтернет-листи під час тестів не надсилаються. Робоча й демонстраційна бази тестами не змінюються.

## Структура

```text
views/                     серверні шаблони Pug, layout, сторінки та include
public/                    CSS та клієнтський JavaScript
src/app.js                 Express-маршрути й обробка помилок
src/server.js              запуск HTTP-сервера та MongoDB
src/config.js              налаштування з .env
src/db.js                  підключення та індекси MongoDB
src/validation.js          серверна перевірка вхідних даних
src/dao/                   доступ до колекцій MongoDB
src/services/              розсилка та формування листів
src/data/                  шаблони та вигадані контакти
scripts/                   початкові дані та перевірка синтаксису
test/                      інтеграційні тести
docs/                      пояснення реалізації та відповідність завданню
requests.http              запити HTTP Client WebStorm
.env.example               приклад конфігурації без секретів
```

Поділ архітектурних рівнів і схеми колекцій наведено в [поясненні реалізації](docs/ПОЯСНЕННЯ.md).

`GET /` виконує `res.render('index', …)`. `views/index.pug` успадковує `layout.pug`, який підключає окремі шаблони шапки, меню, підвалу та модальних вікон. Меню й картки повідомлень формуються циклом `each`. Початкові рядки контактів також формує Pug безпосередньо з MongoDB. Клієнтський JavaScript відповідає за подальші взаємодії та оновлення через JSON API.

HTML-версію кожного листа також формує Pug: `views/emails/message.pug`. Nodemailer додає звичайну текстову версію, тому повідомлення можна читати й без підтримки HTML. Власний текст екранується у HTML-шаблоні.

## Межі навчального застосунку

За замовчуванням сервер слухає тільки `127.0.0.1` і призначений для локальної роботи одного користувача. Авторизація для публічного багатокористувацького сервісу не реалізована. Зміна `HOST` на мережеву адресу потребує окремого налаштування доступу. Під час виконання розсилки друга розсилка відхиляється. Сервер очікує завершення поточної роботи при звичайній зупинці.

Якщо процес аварійно завершується, незавершену розсилку під час наступного запуску позначено «Перервано». Автоматичного повторного надсилання немає, оскільки SMTP міг прийняти листа без встиглого запису результату в базу. Перед повторною розсилкою потрібно перевірити її стан.

У ZIP-архіві є код, lock-файл і документація. `node_modules`, особистий `.env`, база `.data` та створені листи `outbox` до архіву не включаються.

## Якщо запуск не вдався

- **Немає зв’язку з MongoDB**: перевірте, що MongoDB запущено й URI правильний, або скористайтеся `npm run demo`.
- **Порт зайнятий**: зупиніть попередній запуск або задайте, наприклад, `PORT=3001` у `.env`.
- **Не завантажується MongoDB у demo**: перевірте Інтернет і доступ до офіційного сервера завантаження MongoDB. Альтернатива: встановлена MongoDB та `npm start`.
- **SMTP відхиляє листи**: перевірте хост, порт, TLS, пароль і дозволений `MAIL_FROM`. Перегляньте результат для конкретного адресата в історії.
- **Не відкривається `.eml`**: завантажте його з деталей розсилки та відкрийте програмою, яка підтримує MIME-листи, або текстовим редактором для перегляду заголовків.
