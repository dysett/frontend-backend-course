### Текст доповіді та пояснення

Pug перетворює шаблони й дані на HTML. Bootstrap забезпечує готові компоненти інтерфейсу. Nodemailer відповідає за структуру листа та поштовий транспорт.

## Слайд 7 Документ контакту в MongoDB

### Зміст слайда

- **contacts**. Колекція документів адресної книги.
- **_id**. Унікальний ідентифікатор MongoDB.
- **ПІБ та email**. Поля з умови завдання.
- **Часові поля**. Дата створення та останньої зміни.

```javascript
{
  _id: ObjectId("..."),
  lastName: "Коваленко",
  firstName: "Олександр",
  middleName: "Петрович",
  email: "oleksandr@example.com",
  createdAt: ISODate("..."),
  updatedAt: ISODate("...")
}
```

### Текст доповіді та пояснення

MongoDB зберігає записи у вигляді BSON-документів. Для контакту використано окремі поля прізвища, імені та по батькові. Це дозволяє зручно перевіряти значення й сортувати спочатку за прізвищем, потім за ім’ям та по батькові. Поле email містить нормалізовану адресу.

MongoDB автоматично додає поле _id, яке зазвичай має тип ObjectId. У JSON API цей ідентифікатор передається у вигляді рядка, а сервер перед зверненням до бази знову перетворює його на ObjectId. Поля createdAt та updatedAt створює DAO. На слайді наведено схему документа у синтаксисі, подібному до MongoDB shell: ObjectId та ISODate тут позначають відповідні типи, а три крапки є умовними значеннями, а не готовими ідентифікаторами.

## Слайд 8 Підключення та індекси MongoDB

### Зміст слайда

```javascript
const client = new MongoClient(config.mongoUri, {
  serverSelectionTimeoutMS: 5000
});
await client.connect();
const db = client.db(config.dbName);

await db.collection("contacts").createIndex(
  { email: 1 }, { unique: true }
);
await db.collection("contacts").createIndex(
  { lastName: 1, firstName: 1, middleName: 1 },
  { collation: { locale: "uk", strength: 2 } }
);
await db.collection("campaigns").createIndex(
  { createdAt: -1 }
);
```

Унікальний індекс захищає від повторних email на рівні бази даних.

### Текст доповіді та пояснення

Функція connectDatabase створює MongoClient, очікує встановлення з’єднання та обирає базу за назвою з конфігурації. Якщо MongoDB недоступна, очікування обмежено п’ятьма секундами. При невдалому підключенні клієнт закривається, а запуск завершується з повідомленням про помилку.

Після підключення створюються індекси. Унікальний індекс email є головним обмеженням адресної книги. Навіть якщо два запити одночасно намагаються додати однакову адресу, MongoDB збереже лише один запис. Складений індекс ПІБ використовує українське collation. Індекс createdAt зі значенням -1 підтримує отримання найновіших розсилок першими. Код на слайді відформатовано на коротші рядки, його операції відповідають db.js.

## Слайд 9 DAO та українське сортування

### Зміст слайда

- **DAO**. Окремий компонент доступу до даних.
- **find({})**. Вибірка всіх документів.
- **collation**. Правила порівняння українських рядків.
- **sort та toArray**. Упорядкування й отримання масиву.

```javascript
class ContactDAO {
  constructor(db) {
    this.collection = db.collection("contacts");
  }

  async list() {
    return this.collection.find({})
      .collation({ locale: "uk", strength: 2 })
      .sort({
        lastName: 1, firstName: 1,
        middleName: 1, email: 1
      })
      .toArray();
  }
}
```

### Текст доповіді та пояснення

DAO означає Data Access Object, тобто об’єкт доступу до даних. Конструктор ContactDAO отримує підключення db і зберігає посилання на колекцію contacts. Інші частини застосунку викликають метод list(), а деталі MongoDB-запиту залишаються всередині класу.

find({}) створює курсор для всіх документів. collation з locale uk задає українські правила порівняння. strength 2 враховує другорядні відмінності символів і не використовує регістр як третинну відмінність. sort визначає послідовність полів: прізвище, ім’я, по батькові та email. Значення 1 означає зростання. toArray() асинхронно читає результат у масив. На слайді показано частину класу: решта методів відповідає за створення, редагування, пошук за ID та вилучення.

## Слайд 19 Вибір адресатів розсилки

### Зміст слайда

## Слайд 22 Початок роботи CampaignService

### Зміст слайда

- **#busy**. Блокування паралельної розсилки в одному процесі.
- **finally**. Скидання прапорця навіть після помилки.
- **Ліміт**. MAX_RECIPIENTS, за замовчуванням 200.
- **Перевірка адресатів**. Наявність контактів і відповідність вибраним ID.

```javascript
const message = messageInput(input, templates);
if (this.#busy) {
  throw new HttpError(409,
    "Зачекайте завершення поточної розсилки.");
}
this.#busy = true;
try {
  const contacts = message.audience === "all"
    ? await this.contacts.list()
    : await this.contacts.findByIds(
        message.recipientIds
      );
  // Далі: перевірки, запис і розсилка.
} finally {
  this.#busy = false;
}
```

### Текст доповіді та пояснення

CampaignService координує всі етапи розсилки. Спочатку він отримує перевірене повідомлення. Далі приватне поле #busy не дозволяє почати другу розсилку, поки поточна ще виконується. Сервер поверне HTTP 409, а в інтерфейсі на цей час також вимикається кнопка запуску.

Прапорець встановлюється перед асинхронним завантаженням контактів. Наприкінці його обов’язково скидає finally, незалежно від успішного результату. Контакти читаються з MongoDB через DAO. Потім перевіряється, що список не порожній, вибрані записи існують і їх кількість не перевищує maxRecipients. На слайді середину методу замінено коментарем, щоб показати контроль виконання. #busy є блокуванням лише цього процесу Node.js: для кількох серверних процесів потрібен окремий механізм координації.

| sending | Розсилка ще виконується. |
| completed | Усі спроби завершилися успішно в обраному режимі. |
| partial | Частина адресатів успішна, частина має помилки. |
| failed | Усі спроби обробки адресатів завершилися помилкою. |
| interrupted | Після перезапуску виявлено незавершену розсилку. |

CampaignDAO.list() повертає останні 30 записів. recoverInterrupted() не повторює надсилання.

### Текст доповіді та пояснення

Кінцевий стан розсилки визначається лічильниками. Якщо failed дорівнює нулю, стан completed. Якщо succeeded дорівнює нулю, стан failed. Інакше стан partial. Окремі адресати мають власні стани pending, preview, sent або failed. Інтерфейс показує і загальний результат, і деталі кожної адреси.

При запуску сервера recoverInterrupted знаходить записи sending і переводить їх в interrupted. Автоматичного повторного надсилання немає. Це свідоме рішення: SMTP міг прийняти листа, але процес міг завершитися до запису результату у MongoDB. У такій ситуації автоматичний повтор створив би ризик дубліката. Історія сортується за createdAt у спадному порядку та обмежується тридцятьма останніми записами. Детальний маршрут повертає повний текст і масив recipients.

## Слайд 35 Межі реалізації та відповіді на запитання

### Зміст слайда

- **Чому MongoDB?**. Контакти та результати мають природну документну структуру. MongoDB дозволена умовою.
- **Навіщо DAO та Pug?**. DAO відокремлює базу від логіки. Pug формує HTML і виконує вимогу викладача.
- **Що підтверджує sent?**. Прийняття листа SMTP-сервером, а не прочитання чи гарантовану доставку у вхідні.
- **Які межі поточної версії?**. Локальний користувач, послідовна розсилка, один процес та список у пам’яті браузера.
- **Що можна розвинути?**. Авторизацію, серверну пагінацію, чергу завдань і звіти про повернення листів.

### Текст доповіді та пояснення

Поточна версія виконує навчальне завдання, але має чіткі межі. Авторизацію не реалізовано, а сервер за замовчуванням слухає локальну адресу. Розсилки виконуються послідовно в одному процесі. Для великого навантаження доцільно створити чергу завдань, окремий worker, координацію між процесами та серверне отримання сторінок контактів. Це можливі напрями розвитку, а не вже наявні функції.

На запитання про базу відповідаю, що використано MongoDB з колекціями contacts і campaigns. На запитання про Pug показую layout, each і HTML-шаблон листа. На запитання про SMTP пояснюю різницю між прийняттям сервером та доставкою у конкретну скриньку. Для повторного надсилання після аварії потрібна перевірка стану, оскільки програма не гарантує exactly-once доставку. У коді немає автоматичного повтору незавершених розсилок.

### src/config.js

[Відкрити файл](<C:/Codex/Front-end and back-end web application technologies/posobnyk-spamera/src/config.js>)

```javascript
import 'dotenv/config';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

export const projectRoot = fileURLToPath(new URL('../', import.meta.url));

function integer(value, fallback, min, max, name) {
  const parsed = value === undefined || value === '' ? fallback : Number(value);
  if (!Number.isInteger(parsed) || parsed < min || parsed > max) {
    throw new Error(`${name}: очікується ціле число від ${min} до ${max}.`);
  }
  return parsed;
}

export function readConfig(env = process.env) {
  const mailMode = env.MAIL_MODE || 'preview';
  if (!['preview', 'smtp'].includes(mailMode)) throw new Error('MAIL_MODE має бути preview або smtp.');
  if (mailMode === 'smtp' && !env.SMTP_HOST) throw new Error('Задайте SMTP_HOST у .env.');
  if (Boolean(env.SMTP_USER) !== Boolean(env.SMTP_PASS)) throw new Error('Задайте разом SMTP_USER і SMTP_PASS.');
  return {
    host: env.HOST || '127.0.0.1',
    port: integer(env.PORT, 3000, 0, 65535, 'PORT'),
    mongoUri: env.MONGODB_URI || 'mongodb://127.0.0.1:27017',
    dbName: env.MONGODB_DB || 'posobnyk_spamera',
    mailMode,
    mailFrom: env.MAIL_FROM || 'Листоноша <sender@example.com>',
    outboxDir: path.join(projectRoot, 'outbox'),
    maxRecipients: integer(env.MAX_RECIPIENTS, 200, 1, 10000, 'MAX_RECIPIENTS'),
    smtp: {
      host: env.SMTP_HOST,
      port: integer(env.SMTP_PORT, 587, 1, 65535, 'SMTP_PORT'),
      secure: env.SMTP_SECURE === 'true',
```

```javascript
import { ObjectId } from 'mongodb';
import isEmail from 'validator/lib/isEmail.js';
import { HttpError } from './errors.js';

export function objectId(value) {
  if (typeof value !== 'string' || !/^[a-f\d]{24}$/i.test(value)) {
    throw new HttpError(400, 'Некоректний ідентифікатор.');
  }
  return new ObjectId(value);
}

export function contactInput(input) {
  if (!input || typeof input !== 'object' || Array.isArray(input)) throw new HttpError(400, 'Потрібні дані контакту.');
  const fields = {};
  const contact = {};
  for (const [key, label] of Object.entries({ lastName: 'Прізвище', firstName: "Ім’я", middleName: 'По батькові' })) {
    const value = typeof input[key] === 'string' ? input[key].trim().normalize('NFC') : '';
    if (!value || value.length > 80 || !/^[\p{L}\p{M}][\p{L}\p{M} '’ʼ-]*$/u.test(value)) {
      fields[key] = `${label}: введіть від 1 до 80 символів, використовуючи літери, пробіли, апостроф або дефіс.`;
    }
    contact[key] = value;
  }
  contact.email = typeof input.email === 'string' ? input.email.trim().toLowerCase() : '';
  if (!isEmail(contact.email, { allow_utf8_local_part: false }) || contact.email.length > 254) {
    fields.email = 'Введіть коректну електронну адресу.';
  }
  if (Object.keys(fields).length) throw new HttpError(400, 'Перевірте поля форми.', fields);
  return contact;
}

export function messageInput(input, templates) {
  if (!input || typeof input !== 'object' || Array.isArray(input)) throw new HttpError(400, 'Потрібні дані розсилки.');
  let subject = input.subject;
  let text = input.text;
  if (input.templateId) {
    const template = templates.find(item => item.id === input.templateId);
    if (!template) throw new HttpError(400, 'Шаблон повідомлення не знайдено.');
    ({ subject, text } = template);
  }
  if (typeof subject !== 'string' || !subject.trim() || subject.trim().length > 160 || /[\r\n\x00]/.test(subject)) {
    throw new HttpError(400, 'Тема має містити від 1 до 160 символів без перенесень рядків.');
  }
  if (typeof text !== 'string' || !text.trim() || text.trim().length > 10000 || text.includes('\0')) {
    throw new HttpError(400, 'Текст має містити від 1 до 10 000 символів.');
  }
  if (!['all', 'selected'].includes(input.audience)) throw new HttpError(400, 'Виберіть одержувачів.');
  let recipientIds = [];
  if (input.audience === 'selected') {
    if (!Array.isArray(input.recipientIds) || !input.recipientIds.length) throw new HttpError(400, 'Виберіть хоча б одного одержувача.');
    recipientIds = [...new Set(input.recipientIds.map(id => objectId(id).toHexString()))];
  }
  return { subject: subject.trim(), text: text.trim(), templateId: input.templateId || null, audience: input.audience, recipientIds };
}
```

```javascript
export class ContactDAO {
  constructor(db) { this.collection = db.collection('contacts'); }
  async list() {
    return this.collection.find({}).collation({ locale: 'uk', strength: 2 })
      .sort({ lastName: 1, firstName: 1, middleName: 1, email: 1 }).toArray();
  }
  async findByIds(ids) { return this.collection.find({ _id: { $in: ids.map(objectId) } }).toArray(); }
  async create(contact) {
    const document = { ...contact, createdAt: new Date(), updatedAt: new Date() };
    const result = await this.collection.insertOne(document);
    return { ...document, _id: result.insertedId };
  }
  async update(id, contact) {
    return this.collection.findOneAndUpdate({ _id: objectId(id) }, { $set: { ...contact, updatedAt: new Date() } }, { returnDocument: 'after' });
  }
  async delete(id) { return (await this.collection.deleteOne({ _id: objectId(id) })).deletedCount === 1; }
  async seed(contacts) {
    // Повторний запуск не стирає і не змінює наявних контактів.
    return this.collection.bulkWrite(contacts.map(contact => ({ updateOne: {
      filter: { email: contact.email }, update: { $setOnInsert: { ...contact, createdAt: new Date(), updatedAt: new Date() } }, upsert: true
    } })));
  }
}
```

```javascript
import { HttpError } from '../errors.js';
import { messageInput } from '../validation.js';
import { templates } from '../data/templates.js';

export class CampaignService {
  #busy = false;
  constructor(contacts, campaigns, mailer, config) { Object.assign(this, { contacts, campaigns, mailer, config }); }
  async send(input) {
    const message = messageInput(input, templates);
    if (this.#busy) throw new HttpError(409, 'Зачекайте завершення поточної розсилки.');
    this.#busy = true;
    try {
      const contacts = message.audience === 'all' ? await this.contacts.list() : await this.contacts.findByIds(message.recipientIds);
      if (message.audience === 'selected' && contacts.length !== message.recipientIds.length) {
        throw new HttpError(400, 'Деякі контакти вже видалено. Оновіть список одержувачів.');
      }
      if (!contacts.length) throw new HttpError(400, 'Список одержувачів порожній. Додайте контакти.');
      if (contacts.length > this.config.maxRecipients) throw new HttpError(400, `За одну розсилку можна вибрати до ${this.config.maxRecipients} одержувачів.`);
      const campaign = await this.campaigns.create({
        subject: message.subject, text: message.text, templateId: message.templateId,
        mode: this.config.mailMode, status: 'sending', createdAt: new Date(), finishedAt: null,
        total: contacts.length, succeeded: 0, failed: 0,
        recipients: contacts.map(contact => ({ contactId: String(contact._id), email: contact.email,
          name: `${contact.lastName} ${contact.firstName} ${contact.middleName}`, status: 'pending' }))
      });
      // Кожен лист має окремого одержувача. Результат зберігаємо після кожної спроби.
      for (const [index, contact] of contacts.entries()) {
        let result;
        try {
          result = await this.mailer.send(contact, message, String(campaign._id));
          campaign.succeeded += 1;
        } catch (error) {
          result = { status: 'failed', error: error.code === 'EAUTH' ? 'Помилка автентифікації SMTP.' : 'Не вдалося передати або зберегти листа. Перевірте поштові налаштування.' };
          campaign.failed += 1;
        }
        Object.assign(campaign.recipients[index], result);
        await this.campaigns.update(String(campaign._id), { recipients: campaign.recipients, succeeded: campaign.succeeded, failed: campaign.failed });
      }
      campaign.status = campaign.failed === 0 ? 'completed' : campaign.succeeded === 0 ? 'failed' : 'partial';
      campaign.finishedAt = new Date();
      await this.campaigns.update(String(campaign._id), { status: campaign.status, finishedAt: campaign.finishedAt });
      return campaign;
    } finally { this.#busy = false; }
  }
}
```

```javascript
export function createMailer(config) {

  const transport = nodemailer.createTransport(config.mailMode === 'smtp' ? config.smtp : {
```

```javascript
test('real SMTP transport sends separate envelopes and records rejected recipients', async () => {
  const received = [];
  const smtp = new SMTPServer({
    authOptional: true, disabledCommands: ['AUTH', 'STARTTLS'], logger: false,
    onRcptTo(address, session, callback) {
      if (address.address === sampleContacts[0].email) return callback(Object.assign(new Error('Rejected by test SMTP'), { responseCode: 550 }));
      callback();
    },
    onData(stream, session, callback) {
      let raw = '';
      stream.on('data', chunk => { raw += chunk.toString(); });
      stream.on('end', () => { received.push({ raw, recipients: session.envelope.rcptTo.map(r => r.address) }); callback(); });
    }
  });
  await new Promise(resolve => smtp.listen(0, '127.0.0.1', resolve));
  const smtpConfig = { ...config, mailMode: 'smtp', smtp: { host: '127.0.0.1', port: smtp.server.address().port, secure: false, requireTLS: false } };
  const smtpApp = createApp({ db, config: smtpConfig });
  const listener = await start(smtpApp.app);
  try {
    const response = await fetch(`http://127.0.0.1:${listener.address().port}/api/campaigns`, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(message) });
    const result = await response.json();
    assert.equal(response.status, 201); assert.equal(result.mode, 'smtp');
    assert.equal(result.status, 'partial'); assert.equal(result.succeeded, 7); assert.equal(result.failed, 1);
    assert.equal(received.length, 7);
```
