# Сценарій демонстрації двох проєктів на 10 хвилин

Порядок: 00:00–05:00 — «RESTful-сервіс», 05:00–10:00 — «Товстий клієнт». Кожна дія одразу супроводжується готовою реплікою. Текст після **«Одразу говориш»** промовляй уголос, а вказівки після **«Показуєш»** виконуй на екрані. Час передбачає паралельне пояснення й виконання дій.

## Підготовка до початку відліку

### 1. Запусти два проєкти

В окремому терміналі запусти перший проєкт:

```powershell
Set-Location -LiteralPath 'C:/Codex/Front-end and back-end web application technologies/restful-service'
npm run demo
```

У другому терміналі запусти другий проєкт:

```powershell
Set-Location -LiteralPath 'C:/Codex/Front-end and back-end web application technologies/thick-client'
npm run demo
```

Якщо залежності ще не встановлені, заздалегідь виконай `npm ci` в кожній папці. Якщо потрібний проєкт уже працює на своєму порту, використовуй запущений екземпляр.

### 2. Імпортуй актуальну колекцію в Postman

Актуальний файл: [Бібліотека.postman_collection.json](<C:/Codex/Front-end and back-end web application technologies/postman/Бібліотека.postman_collection.json>).

1. Відкрий окрему програму **Postman**.
2. Натисни **Import** та обери цей JSON-файл.
3. Переконайся, що з'явилася колекція **«Бібліотека — API»**.
4. У колекції мають бути дві папки: **«1. RESTful-сервіс»** із запитами **R01–R12** та **«2. Товстий клієнт»** із запитами **T01–T06**.
5. Обери роботу без окремого середовища — **No environment**. Адреси вже задані у змінних колекції: `restUrl` — `http://127.0.0.1:3002`, `clientUrl` — `http://127.0.0.1:3003`.
6. Залиш сховище cookie Postman увімкненим: воно потрібне для запитів до сеансу другого проєкту.
7. Відкрий **«R01 Перевірити стан MongoDB»** та натисни **Send**. Очікуй **200 OK** і `data.status: "ok"`.

R01 також готує випадковий коректний ISBN і очищає попередні змінні ідентифікаторів. Виконай його один раз перед послідовністю R02–R12. Після створення книжки не запускай R01 повторно посеред цієї послідовності.

Якщо посилання відкриває JSON-код у редакторі, це перегляд файлу колекції. Для виконання запитів імпортуй його в Postman. На екрані показуй сам запит, статус і відповідь сервера. Опис структури JSON-файлу колекції до демонстрації не входить.

Використовуй саме актуальну колекцію **«Бібліотека — API»**. У ній українські назви запитів, а тестова REST-книжка має назву **«Тестова книжка»**. Запити самостійно передають ідентифікатори книжки та видачі між кроками.

- Підготуй підсумки `npm test` для кожного проєкту. Встановлення залежностей та запуск тестів виконай до початку відліку.

## Точність пояснень

- У першому проєкті вже є інтерфейс на звичайному JavaScript.
- У другому проєкті AJAX реалізований через polling, без WebSocket і SSE. Дві секунди — пауза після завершення попереднього циклу.
- Cookie містить підписаний ідентифікатор, а дані сеансу зберігаються на сервері. Паролі хешуються.
- Видачі зберігаються в масиві `loans` усередині документа книжки.
- Сеанс авторизації другого проєкту має серверний стан, тому всю систему не слід описувати як повністю stateless.
- Тексти колекції Postman описують лише операції API. Інструкції до виступу містяться в цьому особистому сценарії.
