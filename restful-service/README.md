# RESTful-сервіс бібліотеки

Виконання вправи «RESTful-сервіс» із силабусу Front- та BackEnd-технологій веб-застосувань. Сервіс зберігає книжки в **MongoDB**, реалізує CRUD на **Node.js та Express** і передає дані у **JSON**. Доступ до книжок ізольовано в **BookDAO**. Додаткова бізнес-логіка: видача та повернення примірників, облік доступності й прострочень, статистика фонду.

## Швидкий запуск

Потрібні Node.js **22.12+** і npm. Відкрийте папку `restful-service` у WebStorm або терміналі:

```powershell
npm ci
npm run demo
```

Візуальний інтерфейс: **http://127.0.0.1:3002**. Список книжок у JSON: **http://127.0.0.1:3002/api/books**. Перелік ресурсів API: **http://127.0.0.1:3002/api**. Зупинка: **Ctrl+C**.

## Робота через інтерфейс

Відкрийте головну адресу `http://127.0.0.1:3002/`. Сторінка працює з тією самою MongoDB через JSON API.

- **Додати книжку** відкриває форму опису видання та кількості примірників. **Редагувати** дозволяє змінити ці дані.
- **Видати** біля книжки відкриває форму коду читача й строку видачі на 1–30 діб. Кнопка недоступна, якщо вільних примірників немає.
- **Видачі** біля книжки показує її активні видачі. Вкладка **Активні видачі** показує видачі всіх книжок і дозволяє знайти прострочені.
- **Повернути** приймає примірник у бібліотеку після підтвердження. Кількість доступних примірників і статистика оновлюються.
- **Видалити** потребує підтвердження. Для книжки з активними видачами ця дія недоступна.
- Пошук і фільтри звужують список. **Оновити** завантажує поточні дані. Підказки доступні через **Як користуватися**.

Унизу сторінки є блок **Що відбувається на сервері**: розгорніть його, щоб переглянути останній HTTP-запит, статус і JSON-відповідь. Повідомлення про успіх та помилки показуються біля виконаної дії. Перевірка форм показує власні українські підказки під полями незалежно від мови браузера. Інтерфейс адаптовано для комп’ютера й телефона.

`demo` запускає справжній окремий процес MongoDB через `mongodb-memory-server`. Сховище WiredTiger розташовано в `.data/mongodb`: книжки й активні видачі залишаються після перезапуску. Використовується окрема база `restful_library_demo`. Перший запуск порожньої бази додає три книжки. Порт MongoDB обирається автоматично.

Під час першого запуску demo або тестів пакет завантажує MongoDB 7.0.24 з офіційного сервера. Для Windows архів може займати близько 600 МБ; потрібні Інтернет і вільне місце для завантаження, розпакування та бази. `npm ci` сам сервер MongoDB не завантажує. Якщо MongoDB вже встановлена, можна використати звичайний режим нижче або задати `MONGOMS_SYSTEM_BINARY` — повний шлях до сумісного `mongod.exe`.

## Запуск із власною MongoDB

Запустіть локальну MongoDB або, якщо є Docker, виконайте:

```powershell
docker compose up -d
```

Створіть конфігурацію:

```powershell
Copy-Item .env.example .env
```

За потреби змініть `MONGODB_URI`, `MONGODB_DB`, `HOST` і `PORT` у `.env`:

```dotenv
HOST=127.0.0.1
PORT=3002
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB=restful_library
```

Потім запустіть:

```powershell
npm run seed
npm start
```

`seed` необов’язковий: він додає приклади й пропускає наявні ISBN, зберігаючи їхні дані. У звичайному режимі `npm start` використовує вказану MongoDB, а `npm run demo` завжди використовує окрему локальну базу. Для MongoDB Atlas укажіть власний URI в `.env`. Секрети до архіву не входять.

## Тестування через Postman

1. Запустіть сервіс командою `npm run demo` або `npm start`.
2. У Postman через **Import → Files** імпортуйте `postman/library.postman_collection.json` та `postman/local.postman_environment.json`.
3. Виберіть оточення **Local — RESTful Library**. Значення `baseUrl` за замовчуванням — `http://127.0.0.1:3002`.
4. Відкрийте колекцію **RESTful-сервіс — Бібліотека** та натисніть **Run collection**. Запустіть усі **29 запитів у початковому порядку**, одну ітерацію.
5. Перевірте результати перевірок відповідей у Runner.

Колекція сама генерує валідний випадковий ISBN, зберігає `bookId` і `loanId`, виконує CRUD, видачі та повернення, перевіряє помилки й видаляє створену книжку. Наявні книжки не змінюються. Якщо перервати запуск, тестова книжка може залишитися: її можна повернути й видалити вручну. Перший запит повторно готує змінні для наступного повного запуску.

Для ручної перевірки створення книжки: метод **POST**, URL `{{baseUrl}}/api/books`, **Body → raw → JSON**, тіло:

```json
{
  "title": "Clean Architecture",
  "author": "Robert C. Martin",
  "isbn": "9780134494166",
  "publicationYear": 2017,
  "genre": "Архітектура ПЗ",
  "totalCopies": 2
}
```

Відповідь має статус **201**, заголовок `Location` та об’єкт `data` з новим `id`. Скопіюйте `id` для запитів до одиночної книжки. Повторне створення з цим ISBN поверне **409**.

## Маршрути

| Метод | URI | Призначення | Успіх |
| --- | --- | --- | --- |
| GET | `/api/books` | Усі книжки | 200 |
| GET | `/api/books/:id` | Книжка за ID | 200 |
| POST | `/api/books` | Створення книжки | 201 + Location |
| PUT | `/api/books/:id` | Повне оновлення редагованих полів | 200 |
| PATCH | `/api/books/:id` | Часткове оновлення | 200 |
| DELETE | `/api/books/:id` | Видалення книжки без активних видач | 200 |
| POST | `/api/books/:id/loans` | Видача одного примірника | 201 + Location |
| GET | `/api/books/:id/loans` | Активні видачі книжки | 200 |
| GET | `/api/books/:id/loans/:loanId` | Окрема активна видача | 200 |
| DELETE | `/api/books/:id/loans/:loanId` | Повернення примірника | 200 |
| GET | `/api/loans` | Активні видачі всіх книжок | 200 |
| GET | `/api/loans?overdue=true` | Прострочені видачі | 200 |
| GET | `/api/statistics` | Статистика фонду | 200 |
| GET | `/api/health` | Перевірка зв’язку з MongoDB | 200 |

Колекції повертають усі відповідні записи без пагінації. Для `/api/books` доступні `q` (буквальний пошук без урахування регістру за назвою, автором або ISBN), `genre` (точний збіг) та `available=true|false`. Їх можна поєднувати. `overdue=false` або відсутність цього параметра повертає всі активні видачі.

Успішна відповідь має вигляд `{ "data": ... }`; список книжок додатково містить `meta.count`. Помилка:

```json
{
  "error": {
    "code": "NO_COPIES_AVAILABLE",
    "message": "Немає вільних примірників."
  }
}
```

Основні статуси: **400** — некоректні поля або ID, **404** — ресурс відсутній, **405** — метод не підтримується, **409** — конфлікт бізнес-правил або ISBN, **413** — тіло більше 32 КБ, **415** — неправильний Content-Type, **503** — MongoDB недоступна під час перевірки health. `OPTIONS` для ресурсів API повертає дозволені методи в заголовку `Allow` і JSON.

## Правила предметної області

- Обов’язкові поля книжки: `title`, `author`, `isbn`, `publicationYear`, `genre`, `totalCopies`. ISBN-13 перевіряється за контрольною цифрою; пробіли й дефіси вилучаються. ISBN унікальний.
- `publicationYear` — ціле число від 1 до поточного року UTC; `totalCopies` — ціле число від 1 до 100. Клієнт не може змінювати ID, часові позначки, видачі чи обчислену доступність через CRUD книжок.
- Для видачі передають `{ "readerId": "reader-001", "days": 7 }`. `readerId` — умовний ідентифікатор читача до 64 символів: літери, цифри, дефіс або підкреслення. Регістр має значення. `days` — ціле число 1–30, стандартно 14.
- Одна видача займає один примірник. Читач може мати лише один примірник певної книжки одночасно. Дата видачі та строк повернення обчислюються сервером. Доба становить 24 години; час повертається в UTC у форматі ISO 8601.
- Без вільних примірників видача відхиляється. Фонд не можна зменшити нижче кількості активних видач. Книжку з активними видачами не можна видалити.
- `DELETE` видачі означає повернення: активний підресурс вилучається, примірник знову доступний. Повторне повернення дає 404 і не змінює фонд. Архів повернених видач у цій моделі не ведеться.
- Видача прострочена, якщо `dueAt` строго менша за поточний серверний час. Статистика рахує назви книжок, загальний фонд, видані й доступні примірники та прострочені видачі.

## Архітектура

```text
Postman / HTTP-клієнт
  → Express Router
  → Controller                 HTTP, JSON, статуси та Location
  → BookService                валідація, правила видачі, представлення даних
  → BookDAO                    запити, атомарні зміни та агрегації MongoDB
  → MongoDB                    колекція books, унікальний індекс isbn
```

Пояснення моделі даних, атомарності та відповідності вимогам: [docs/ПОЯСНЕННЯ.md](docs/ПОЯСНЕННЯ.md).

```text
src/app.js                     створення Express-застосунку
src/server.js                  запуск HTTP і MongoDB, demo, зупинка
src/config.js                  .env і налаштування
src/db.js                      підключення, журналювання й індекс ISBN
src/routes/books.js            URI та HTTP-методи
src/controllers/               перетворення HTTP-запитів і відповідей
src/services/                  бізнес-логіка
src/dao/                       доступ до MongoDB
src/validation.js              перевірка вхідних даних
public/                        HTML, CSS і JavaScript інтерфейсу
scripts/                       seed, синтаксична перевірка, ZIP
test/                          інтеграційні тести зі справжньою MongoDB
postman/                       колекція та оточення Postman
requests.http                  запити для HTTP Client WebStorm
compose.yaml                   необов’язкова локальна MongoDB через Docker
```

## Автоматичні перевірки

```powershell
npm run check
npm test
```

`check` перевіряє синтаксис JavaScript, включно з клієнтським кодом, та коректність JSON. **18 інтеграційних тестів** перевіряють видачу сторінки й статичних файлів, CRUD, валідацію, ISBN, бізнес-правила, пошук, статистику, прострочення, конкурентні видачі й повернення. Окремий тест зупиняє та повторно запускає процес MongoDB і перевіряє збереження книжки та її видачі. Тести використовують власні тимчасові бази; робочу й демонстраційну бази не змінюють.

## Архів для здачі

```powershell
npm run pack:submission
```

У батьківській папці з’явиться `RESTful-сервіс.zip`. Архів містить код, lock-файл, документацію, тести й Postman. Залежності `node_modules`, персональний `.env` та дані `.data` не додаються.

## Межі застосунку та усунення проблем

Сервіс призначений для локального навчального використання й за замовчуванням слухає `127.0.0.1`. Облікові записи й авторизація читачів не реалізовані. Підключення перевикористовується між запитами; сервер не зберігає клієнтську сесію. Браузерний інтерфейс є додатковим клієнтом JSON API; усі операції також доступні в Postman.

Якщо порт зайнятий, змініть `PORT` у `.env` і `baseUrl` у Postman. Якщо MongoDB недоступна, перевірте URI й запущений процес або використайте `npm run demo`. Якщо demo не може завантажити MongoDB, перевірте Інтернет і місце на диску або використайте встановлений сервер. Після зміни `.env` перезапустіть сервіс.
