# Товстий клієнт — Книгосховище

Вправа «Товстий клієнт» із розділу «Контрольні вправи до самостійної роботи» силабусу Frontend/Backend. Це окрема перероблена версія попереднього `restful-service`: **React + Bootstrap 5** у браузері, **Node.js + Express** на сервері, **MongoDB**, REST JSON API, адміністративні сеанси та автоматичне AJAX-оновлення.

## Швидкий запуск

Потрібні **Node.js 22.12+**, npm і вільний порт 3003. У терміналі в цій папці:

```powershell
npm ci
npm run demo
```

Команда сама збирає React і запускає локальну MongoDB. Під час першого запуску `mongodb-memory-server` завантажує офіційний сервер MongoDB 7.0.24; Windows-архів займає близько 600 МБ. Потрібні інтернет і місце на диску. Наступні запуски перевикористовують завантажений сервер. Якщо MongoDB вже встановлена, можна задати `MONGOMS_SYSTEM_BINARY` або використати звичайний режим нижче.

- Каталог читача: **http://127.0.0.1:3003/**.
- Адміністратор: **http://127.0.0.1:3003/admin**.
- Демонстраційний вхід: **admin / DemoLibrary!2026**.
- JSON без входу: **http://127.0.0.1:3003/api/books**.
- Зупинка сервера: **Ctrl+C**.

Демонстраційний пароль застосовується лише в режимі `demo`, який дозволений на `127.0.0.1` через HTTP. Звичайний запуск не створює цього облікового запису. У `.data/mongodb` зберігаються книжки, видачі, адміністратор і серверні сеанси; у `.data/session-secret` — випадковий секрет підпису cookie. Дані переживають перезапуск. Порожня демонстраційна база отримує три приклади книжок. Доступність бібліотеки не залежить від зовнішніх CDN: React, Bootstrap, іконки та шрифти віддаються локально.

## Як користуватися

**Читач.** На головній сторінці можна шукати за назвою, автором та ISBN, вибирати жанр, сортувати за назвою або роком і показувати лише доступні книжки. Натискання на обкладинку чи назву відкриває деталі. Логін не потрібен. Для отримання примірника читач звертається до бібліотекаря.

**Адміністратор.** Після входу доступні додавання, редагування й видалення книжок, видача примірника читачеві та повернення. У розділі «Активні видачі» є пошук і фільтр прострочень. Для видалення та повернення потрібне підтвердження. Вилучення книжки з активними видачами і зменшення фонду нижче кількості виданих примірників заборонені також на сервері. Валідація форм показує українські повідомлення. Сеанс діє 30 хвилин після входу; «Вийти» негайно знищує його на сервері.

**Автоматичне оновлення.** Кожна відкрита сторінка виконує `fetch`-запити до JSON API кожні **2 секунди після завершення попередніх запитів**. Додавання, редагування, видалення, видачі й повернення відображаються автоматично в інших вкладках і незалежних браузерних сеансах. Зміни через Postman також підхоплюються. Пошуковий запит і фільтри зберігаються. Повного перезавантаження сторінки немає. Після втрати зв’язку показується повідомлення, опитування продовжується; невдалі операції запису автоматично не повторюються.

### Демонстрація AJAX для захисту роботи

1. Відкрийте каталог у звичайному вікні браузера, а `/admin` — в іншому браузері або приватному вікні.
2. Увійдіть адміністратором і додайте книжку з унікальним коректним ISBN-13.
3. Переконайтеся, що вона з’явилася в першому вікні без натискання кнопок і перезавантаження.
4. Видайте єдиний примірник. У каталозі зміниться доступність; із фільтром «Лише доступні» книжка зникне.
5. Поверніть примірник. Книжка знову з’явиться.

## Власна MongoDB та адміністратор

Запустіть MongoDB локально або через необов’язковий Docker Compose:

```powershell
docker compose up -d
Copy-Item .env.example .env
node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
```

У `.env` вставте згенерований секрет у `SESSION_SECRET` та задайте власні `ADMIN_USERNAME` і `ADMIN_PASSWORD` (12–128 символів). За потреби змініть адресу MongoDB, базу, хост і порт. Потім:

```powershell
npm run admin:create
npm run seed
npm start
```

`admin:create` створює нового адміністратора та відхиляє повторний логін. `seed` необов’язковий і не переписує наявні ISBN. Після створення адміністратора приберіть `ADMIN_PASSWORD` з `.env`: сервер перевіряє збережений хеш, цей параметр йому не потрібен. `.env` не включається до архіву. Для production потрібно встановити `NODE_ENV=production`, точний `PUBLIC_ORIGIN=https://ваш-домен`, `COOKIE_SECURE=true`, використовувати HTTPS і захищену MongoDB. `TRUST_PROXY=true` вмикайте лише за власним довіреним reverse proxy, що перезаписує forwarded-заголовки й закриває прямий доступ до Node.js. Секрет сеансів має залишатися стабільним між запусками.

## Postman

1. Запустіть `npm run demo`.
2. Імпортуйте `postman/library.postman_collection.json` і `postman/local.postman_environment.json`.
3. Виберіть **Local — Thick Client Library**. Для власної бази змініть `adminUsername`, `adminPassword` і за потреби `baseUrl`.
4. Залиште cookie jar увімкненим. Запустіть **усі 34 запити за початковим порядком**, одну ітерацію.

Колекція отримує CSRF-токен, входить, зберігає оновлений токен і використовує cookie сеансу. Потім перевіряє CRUD, видачі, повернення, фільтри, статистику та помилки. Наприкінці видаляє свою тестову книжку, перевіряє CSRF-захист, виходить і перевіряє заборону змін без сеансу. Наявні книжки не змінюються. Перерваний запуск може залишити тестову книжку. Пароль у файлі оточення — лише публічний локальний demo-пароль.

Колекцію також можна виконати через Newman:

```powershell
npx newman run postman/library.postman_collection.json -e postman/local.postman_environment.json
```

Для ручного запису спочатку виконайте `GET /api/auth/session`, потім `POST /api/auth/login` з JSON `{ "username": "admin", "password": "DemoLibrary!2026" }` і заголовком `X-CSRF-Token` з першої відповіді. Після входу використовуйте **новий** `data.csrfToken`. Cookie передається автоматично. Приклади для WebStorm HTTP Client є в `requests.http`.

## API

Успіх: `{ "data": ... }`, список книжок також має `meta.count`. Помилка: `{ "error": { "code": "...", "message": "..." } }`.

| Метод | Шлях | Доступ / призначення |
| --- | --- | --- |
| GET | `/api/auth/session` | Стан сеансу, користувач або `null`, CSRF-токен |
| POST | `/api/auth/login` | Вхід; потрібні початкова cookie та CSRF |
| POST | `/api/auth/logout` | Адміністратор + CSRF; знищення сеансу |
| GET | `/api/books` | Відкритий каталог; `q`, `genre`, `available=true/false` |
| GET | `/api/books/:id` | Відкрита інформація про книжку |
| POST | `/api/books` | Адміністратор + CSRF; створення, 201 + Location |
| PUT / PATCH | `/api/books/:id` | Адміністратор + CSRF; повне / часткове оновлення |
| DELETE | `/api/books/:id` | Адміністратор + CSRF; видалення |
| GET | `/api/loans` | Адміністратор; усі видачі, `overdue=true` — прострочені |
| GET | `/api/books/:id/loans` | Адміністратор; видачі книжки |
| GET | `/api/books/:id/loans/:loanId` | Адміністратор; одна видача |
| POST | `/api/books/:id/loans` | Адміністратор + CSRF; `{ "readerId": "reader-001", "days": 14 }` |
| DELETE | `/api/books/:id/loans/:loanId` | Адміністратор + CSRF; повернення |
| GET | `/api/statistics` | Відкрита агрегована статистика без кодів читачів |
| GET | `/api/health` | Перевірка MongoDB |

Основні статуси: 400 — валідація, 401 — немає чинного сеансу / неправильні облікові дані, 403 — CSRF / чужий origin або host, 404 — ресурс відсутній, 405 — метод не підтримується, 409 — конфлікт ISBN або правил видачі, 413 — JSON понад 32 КБ, 415 — неправильний Content-Type, 429 — перевищення ліміту, 503 — MongoDB недоступна під час health. `OPTIONS` для ресурсів книжок повертає `Allow`.

Книжка має `title`, `author`, `isbn`, `publicationYear`, `genre`, `totalCopies`. ISBN-13 унікальний і перевіряється за контрольною цифрою. Фонд — 1–100; рік — від 1 до поточного року UTC. Видача — на 1–30 діб, стандартно 14. `readerId` містить до 64 літер, цифр, дефісів або підкреслень. Один читач не може одночасно отримати два примірники однієї книжки. Строки визначає сервер у UTC. Історія повернених видач не зберігається.

## Архітектура та захист

```text
React-компоненти → api.js / fetch → Express Router
                                   → middleware: сесія, роль, CSRF
                                   → Controller → Service → DAO → MongoDB
Postman ───────────────────────────→ той самий JSON API
```

- `client/src/`: React-компоненти каталогу й адміністратора, стан, фільтри та AJAX; Bootstrap імпортується як npm-залежність.
- `src/routes`, `src/controllers`: HTTP, статуси, JSON, сеанси.
- `src/services`: валідація та бізнес-правила; scrypt-перевірка пароля.
- `src/dao`: усі предметні запити MongoDB; атомарні зміни видач.
- `src/middleware`: серверна перевірка адміністратора, CSRF, Origin та Host.
- `dist/`: зібраний клієнт, який віддає Express. У браузері немає доступу до MongoDB або секретів.

Cookie містить лише підписаний ID, має `HttpOnly`, `SameSite=Strict`, у HTTPS-режимі — `Secure`. Дані сеансу зберігає `connect-mongo`, прострочені записи прибирає TTL-індекс. Успішний вхід регенерує ID і CSRF-токен; вихід вилучає сеанс. Абсолютний строк авторизації перевіряється сервером і не продовжується через опитування. Паролі зберігаються як scrypt-хеші з випадковою сіллю. Входи обмежені 10 невдалими спробами за 15 хвилин на IP; API — 600 запитами за хвилину на IP.

Усі зміни та читання кодів читачів захищені на сервері. Записи потребують CSRF-токена і перевірки походження; CORS не відкритий. React екранує текст, `dangerouslySetInnerHTML` не використовується. Helmet встановлює CSP без inline-скриптів, заборону iframe та інші заголовки. Вхідні поля й типи мають білий список; оператори MongoDB з HTTP не приймаються, регулярний вираз пошуку екранується. Повідомлення помилок не містять stack trace та рядків підключення.

Розгорнуте пояснення відповідності силабусу: [docs/ПОЯСНЕННЯ.md](docs/ПОЯСНЕННЯ.md).

## Перевірки та здача

```powershell
npm run check
npm test
npm run test:ui
npm run pack:submission
```

`check` перевіряє синтаксис JS та JSON; JSX перевіряє Vite під час збірки. `npm test` запускає 25 інтеграційних тестів зі справжньою окремою MongoDB. Вони перевіряють бізнес-логіку, конкурентні видачі, захист і збереження даних та сеансів після перезапуску.

`test:ui` використовує Playwright та встановлений Google Chrome, створює власну тимчасову MongoDB і вебсервер. Перевіряє AJAX між двома незалежними сеансами, форми, CRUD, видачу/повернення, XSS-екранування, вихід, відновлення з’єднання та мобільний вигляд. Скріншоти записує в `docs/screenshots`. Якщо Chrome немає, встановіть Chromium і вкажіть його:

```powershell
npx playwright install chromium
$env:UI_BROWSER = 'chromium'
npm run test:ui
```

Тести не змінюють demo або власну робочу базу. `pack:submission` створює **`Товстий-клієнт.zip` у батьківській папці** з кодом, зібраним клієнтом, lock-файлом, документацією, тестами та Postman. `node_modules`, `.env`, `.data`, журнали й тимчасові файли не додаються.

Межі навчальної реалізації: один екземпляр Express; лічильники rate limit зберігаються в пам’яті цього процесу. Для кількох екземплярів потрібне спільне сховище лімітів. Каталог завантажується цілком без серверної пагінації. Реєстрація читачів, відновлення пароля та MFA до вправи не входять.
